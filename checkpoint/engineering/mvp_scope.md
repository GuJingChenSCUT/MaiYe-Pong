| --- | --- | --- |

## 六项产品定义

### 用户问题

消费者要在不同页面反复核对商品是否同规格、能否送到指定地址、完整现金支出、优惠资格和售后责任，并在条件变化时重新决定是否继续。我们拟减少这些核对与操作负担，让用户在明确边界内委托一次购物。省时、正确性和再次使用意愿都是待实测的价值假设。

### 核心流程

1. 买家提出需求；系统保存任务，澄清会影响购买的缺项。
2. 商品分析读取两家获准来源，核对规格、地址费用、库存、交付和退货条件；保留来源定位与观察时间。
3. 业务服务计算现金和适用优惠；支付权益顾问解释取舍。无可用权益时明确说明，不能虚构增益。
4. 买家规划提出方案；服务端核验并生成不可变快照。用户看到商品、总额、收款方、关键条件和有效期后明确确认。
5. 可信后端把确认绑定到同一快照和委托。交易 worker 原子核对最新受信版本、授权、预算与收款方后取得派发权，执行商户订单和付款流程。
6. 页面回读权威订单及付款状态，展示回执。新事实触发补查、改选、重新确认或停止；不能静默替换已批准方案。

停止入口始终直接调用可信后端，不经过模型排队。模型超时、页面关闭或重新打开，均不应使已持久化任务失去可追踪状态。

V1 明确区分硬条件与偏好：现金上限、所需规格、数量、必要退货条件和送达时限先作门禁；`lowest_cost`、`fastest_delivery`、`easiest_returns` 只在合格候选内排序。未提供偏好时须明确展示默认最低现金；用户已选最快或易退货时不能静默回到最低价，也不能为了演示强制从商户 A 改选 B。权益由服务判断适用资格、时效、互斥关系和优惠实例去重；待得积分、返现或未知资格不能降低本次现金支出。商户接受是独立事实，支付成功不能替代它。

本地原子检查不能锁住外部商户的价格和库存。成交适配器还必须支持固定报价，或对商品、总额等条件作等价的提交校验；外部重定价需要停止旧方案并重新确认。无法保证这些条件的来源只用于研究比较。

### 输入与输出

| 对象 | 必须包含 | 未知时的处理 |
| --- | --- | --- |
| 用户需求 | 规格、数量、现金上限、香港目的地、时限、不可接受条件 | 澄清；不自动猜测硬约束 |
| 商品报价 | 商户、SKU、地区版本、费用明细、库存、履约及退货条款、有效期、证据 | 不完整的候选可供研究，但不能进入可执行快照 |
| 优惠资格 | 规则、适用主体、门槛、期限、叠加关系、唯一应用实例 | 不扣减未知优惠，不要求用户提供无关个人资料 |
| 模型输出 | 分开的事实、服务计算引用、建议和未知项 | 每项未知说明影响及下一步，关键缺口阻断执行 |
| 用户确认 | 同一快照摘要、金额、收款方、关键条件、有效期及可信身份 | 没有有效确认不得派发；过期和关键变更需新确认 |
| 交易结果 | 原 operation、商户订单引用、付款引用、状态与回执 | UNKNOWN 保留预留，只查询原操作，不视作失败 |

银行卡凭据、支付密钥和其他商户的私有资料不进入模型上下文。支付资料采集方式由选定 PSP 的实际能力决定。

### 完成标准

“代码落地”“本地测试通过”“模型接通”“商户接通”“官方沙盒通过”和“真实资金可用”分别登记。停点一已进入授权编码，当前整体验收仍未完成；新的验收在取得对应证据前保留 `not_run`，明确缺外部依赖的项目记为 `blocked`。本地子项通过不自动升级整个 AC。

团队的工程目标是在获准商户的测试订单环境和一个官方 PSP 沙盒中完成同一任务链。测试付款不得驱动会实际履约或扣费的生产订单。若只有本地模拟器，可作为明确标注的控制流演示，不能升级为官方沙盒通过。赛事附件本身未规定必须发生真实资金扣款；演示环境的接受边界按主办方说明确认。

### 首版不做的内容

不做跨店拆单、CNY 付款执行、充值余额、跨平台积分通兑、无人争议裁决或部分退款。不把搜索覆盖范围宣称为全市场，不将预计积分当本次现金，不因用户没有回复而自动延长授权。首版不以多 Agent 数量、所接平台数量或框架复杂度作为成果。

### 关键术语

| 术语 | 本项目定义 |
| --- | --- |
| 受控代办 | 在用户需求与可执行授权内完成任务，越界停止且允许用户接管 |
| Agent | 使用模型选择查证、澄清或建议动作的任务角色；不拥有资金授权权 |
| Skill | 有触发条件、步骤、工具范围、输出和验收的版本化操作规程 |
| 工具 | Schema 加实际 handler；调用权限及业务规则由可信服务检查 |
| 知识库 | 可定位、可审核、具有适用范围和时效的业务证据及案例 |
| Snapshot | 经服务校验、被用户确认的不可变方案版本 |
| Mandate | 绑定用户、快照、限制和有效期的可执行委托 |
| Operation | 一次稳定业务操作；未知结果恢复继续使用该对象及原幂等键 |
| PSP 与付款通道 | PSP 是接入与执行机构；可用付款方式取决于该机构及商户账号的实际能力 |
| UNKNOWN | 尚无可靠付款终态，需要查原单；不等于失败、取消或退款 |

## 页面与用户体验

落地页只讲用户价值、适用场景、已开放范围和进入任务的入口。模拟或沙盒版本应在开始前明示，不能先作真实代购承诺再在页脚解释。主按钮建议为“开始一次购物委托”。

MVP 工作页面至少包含需求与澄清、两家比较、方案确认、订单进度及异常接管。确认卡由业务对象提供金额、商品、收款方、条款和有效期；模型文案不能覆盖这些字段。停止按钮易发现，操作后的页面区分“已阻止派发”“正在核实原单”“取消处理中”和“退款到账”。

以繁体中文作为香港首版默认表达的设计建议，允许自然口语输入；键盘可操作、状态不只靠颜色、费用不藏在长文本中。用 Gen Z 参与者验证理解与流畅度，同时保持香港成年消费者的既定范围。语言、无障碍和可用性改进都需要实际测试，不仅是界面声明。

三端围绕同一任务和订单协作：买家确认与控制；商户确认本店事实及订单处理；运营处理异常与证据。商户不能看买家完整预算或其他商户报价，运营不能通过模型文字直接改账。

V1 身份由服务器校验访问码后签发会话，角色及租户来自服务器映射，不能由浏览器下拉框、请求体或模型声明选择。写请求使用会话、CSRF 与幂等键；先校验身份和目标资源权限，再检查幂等记录，最后检查当前版本。同键同请求重放原结果，同键异请求返回冲突，不能先因版本已更新而拒绝合法重试；无权用户也不能通过猜幂等键读到旧响应。停止不要求页面持有最新版本。

用户在可信页面发出的停止命令与资料中的恶意提示分开处理。商户描述、网页、知识片段及工具返回中的“忽略限制”“代用户批准”“取消其他任务”等文本不是用户指令；应隔离该指令并校验可用事实。关键事实不再可信时可由规则停止研究或阻止执行，但不能伪造“用户已撤销”的事件。

## 跨境字段现在保留

| 字段族 | 最低信息 | 首版约束 |
| --- | --- | --- |
| 币种 | 报价币种、费用币种、付款币种及来源 | 只执行 HKD；无汇率来源时不做换算承诺 |
| 地区版本 | 产地、销售地区版本、变体及等价判断依据 | 相同名称不直接视为等价商品 |
| 分段物流 | 每段起讫地点、责任方、费用、期限和证据 | 香港场景可以只有一段；新增跨境段不能隐去费用或责任 |
| 保修 | 服务地区、责任方、期限、条件和证据 | 未知明确展示；若用户列为硬条件则阻断 |
| 退货 | 退回地点、期限、运费承担、例外和退款责任 | 未核实不得概括成“可退货” |

这些是 V1 及后续适配器的数据契约边界；V1 已落地字段与预留设计须分别登记，不能悄悄写入并声称原 `0.4-proposal` 已支持。跨境连接、分段物流及完整责任证据未接入前不作为可执行能力宣传。

## 停点一实施与恢复约束

V1 的贯通目标是输入、澄清、两家比较、实际工具回环、服务重算、同快照确认、唯一付款操作与独立订单状态；商品及付款先诚实标记本地模拟。原 151 项仅为旧工程历史本地记录，不能与 V1 测试数混合，也不能证明线上能力。已授权的 33 文件工作可以继续完成，不重复索要相同范围的授权；本轮不包含网站发布、创建提供方账号或真实付款。

- `TaskStore` 与 `StageOneKernel` 共享同一个 SQLite connection。任务修改、事实和收款方当前版本、快照／挑战／授权、付款操作、预算预留及派发命令由同一 `BEGIN IMMEDIATE` 事务维护；内核不另建独立库，也不在外层事务中自行提交。
- 模型运行有持久 run 状态和 fencing lease，防止停止或新版本之后旧结果覆盖任务。模型租约过期可以重新调度研究，但绝不是重发付款的理由。
- 确认只消费同一 `challenge_id` 并建立绑定同一 `snapshot_id` 的授权与 `operation_id`。用户所见摘要、服务器重算金额、收款方及派发载荷必须一致；旧快照不能因请求重试变成新方案。
- 派发 claim 原子检查当前条件、事实、授权、预算和收款方映射，更新同一派发命令；claim 后崩溃即进入原操作查询／对账，不能借模型重试、HTTP 重试或 worker 租约创建第二次付款。UNKNOWN 保留预算直到有权威终态。
- 本地数据库事务只能保护本地受信记录。外部成交仍需要商户固定报价或等价条件提交与官方 PSP 合同；这些依赖未取得时，AC06 保持 `blocked`。

停点一交接需提交实际改动、分层测试证据、未完成项与下一步；本文件不预填通过数量。真实模型、官方商户／PSP、部署及真实用户结果各自独立验收。
